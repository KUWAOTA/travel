# ラクス／RAKUS Vietnam応募 スキル基準の通過確率 v0.9

作成日: 2026-07-13

## 1. 前提

この推定には、現年収625万円も求人年収678万～966万円も使用しない。選考確率は、現在のスキルと経験が求人業務にどの程度適合するかだけで見積もる。

情報を追加確認しても、本人のスキルそのものは変わらない。変わるのは次の2点だけである。

- 書類で事実を証明できる強さ。
- 面接で具体的に説明できる確率。

会社の実採用データ、応募者数、他候補者の質は不明であるため、以下は求人票と本人の経験から作った主観的推定である。

必須要件への適合は強い。一方、実際の赴任後業務の中心であるコードレビュー、複数人育成、プロセス改善、Agile、チームリードには経験差がある。「テックリードとして完成している候補」ではなく、「実装力と育成の芽があり、現地でリード役へ広げられる候補」という位置づけになる。

## 3. スキルだけから見た通過確率

### 中心推定

| 段階 | 現在の書類で応募 | 残情報を確認し、説明を詰めた後 |
| --- | ---: | ---: |
| エージェント推薦 | 72% | 82% |
| 企業書類選考 | 48% | 58% |
| 一次面接通過（書類通過後） | 50% | 60% |
| 二次・最終・SPI通過（一次通過後） | 50% | 55% |
| 最終内定（企業応募時点から） | 12% | 19% |

### 妥当レンジ

- 企業書類通過: 現在35～60%、情報整理後45～70%。
- 最終内定: 現在8～18%、情報整理・面接準備後13～28%。

最終内定の中心値は、概算として次のように計算している。

- 現在: 書類48% × 一次50% × 以後50% ≒ 12%。
- 情報整理後: 書類58% × 一次60% × 以後55% ≒ 19%。

これは年収による補正を一切含まない。

## 4. 現在のスキルで通る可能性がある理由

求人の必須スキルは、Webアプリケーション開発3年以上と海外環境への適応・意欲である。本人は両方を明確に満たす。

さらに、歓迎要件である人材育成について、対象は1名ながら内容が具体的である。

- 3サイクルに分けた課題。
- 修正ラリーを含む反復レビュー。
- 設計判断の理由を本人に説明させる指導。
- 先輩開発メンバー5名を巻き込んだレビュー機会。
- 受講者の質問が保守性を意識した内容へ変化。

技術面でも、単なる指示どおりの実装だけではない。

- v1.2で自動検品機能の設計・実装を主担当。
- 5～6段のコールバックをPromiseで整理。
- Wiresharkで通信状態を調査し、非同期競合を修正。
- v1.2で残った状態管理課題をv1.3でクラス分割へ反映。
- 約3,000行の画面クラスから約300行を段階的に分離。

ラクスが「完成済みの大規模組織テックリード」だけを求めるなら厳しいが、プレイヤー経験と育成経験を持ち、日本勤務期間に自社プロセスを学んでから赴任する成長枠も含むなら、十分に書類・面接対象になり得る。

## 5. 現在のスキルで落ちる可能性がある理由

### コードレビュー

求人ではGitLabのMerge Requestを使うPull Requestベースのレビューが明記されている。本人にはGitHub利用経験はあるが、PRレビュー経験はない。新人育成での対面レビューは評価材料になるものの、チームの日常開発レビューとは別物である。

### プロセス改善・Agile

単体テスト標準化とAI調査共有は試行段階で、継続運用に至っていない。正式なAgile経験もない。赴任後の主要業務へ直接対応する実績としては弱い。

### リード範囲

機能の設計・実装主担当経験はあるが、複数人へのタスク配分、進捗管理、評価、採用、育成計画、プロジェクト全体の意思決定は経験していない。

### 技術スタック

Java Web経験は活かせるが、Spring Boot、PHP、GitLab、Linux、PostgreSQL等の直接経験が弱い。技術の移行可能性を説明する必要がある。

## 6. 情報を詰めると確率が上がる理由

情報確認によって新しいスキルが増えるわけではない。それでも最終内定の中心値を12%から19%へ上げるのは、現在すでに持っている経験が面接で正確に伝わるようになるためである。

特に効果があるのは次の確認である。

1. v1.2～v1.4の開始・リリース月を確定する。
2. Promiseと2件の接続競合について、原因、変更、テスト、再発有無を分ける。
3. v1.3の状態クラス数、状態一覧、テスト内容を確認する。
4. 新人育成の実施記録と受講者コメントを整理する。
5. AIと単体テスト施策は、成功部分と未定着部分を短く説明する。
6. 職務経歴書を3～4ページ相当へ削る。
7. PMや既存設計への不満を、制約・判断・改善として説明できるよう面接練習する。

## 7. スキル評価からの応募判断

応募は推奨する。

理由は、必須要件を満たし、求人に珍しく合う「海外生活への強い適応」「新人育成」「ハンズオン実装」の組合せがあるためである。弱点は大きいが、求人票上で正式なリーダー経験やAgile経験は必須条件として明記されていない。

ただし、本命一本に絞るのは勧めない。現地テックリードとして完成済みの候補と比較された場合は不利であり、書類通過後も3回面接とSPIがある。エージェントへ出して市場評価を得つつ、海外志向・育成経験を評価するプレイヤー寄り求人も並行するのが妥当である。
