# ラクス／RAKUS Vietnam応募 通過確率の推定 v0.8

> この版は廃止。給与帯に関する表現が選考難度の説明へ混在したため、スキルだけで再評価した `application_probability_estimate_v0.9_skill_based.md` を正本とする。

作成日: 2026-07-13

## 1. 結論

現時点の書類セットでも応募する価値はある。ただし、求人名が「テックリード」で、主要業務がコードレビュー、育成、Agileを含むプロセス改善、技術選定、チームリードであるのに対し、正式なリーダー経験、定常的なPull Requestレビュー、Agile経験がない点は大きな弱みである。

推定中心値は次のとおり。

| 段階 | 現在のv0.8 | 残情報を確認・反映後 |
| --- | ---: | ---: |
| エージェントが推薦可能と判断 | 65% | 75% |
| 企業の書類選考通過 | 38% | 46% |
| 一次面接通過（書類通過後） | 42% | 52% |
| 最終内定（企業応募時点から） | 8% | 14% |

妥当と考えるレンジは次のとおり。

- 企業書類通過: 現在25～50%、追加確認後32～58%。
- 最終内定: 現在5～12%、追加確認後9～20%。

単一点の精度は低い。応募者数、他候補者の経歴、採用枠、エージェントの推薦力、SPI、面接官との相性が不明なためである。数値は意思決定用の目安であり、ラクス社の実採用統計ではない。

## 2. 履歴書と職務経歴書を別々に評価できない理由

企業は通常、履歴書と職務経歴書をセットで評価する。履歴書単体には、学歴、在籍状況、資格、海外志向等はあるが、テックリード業務への適合を判断できる情報が少ない。

各書類の役割は次のとおり。

| 書類 | 合否への役割 | 現状評価 |
| --- | --- | --- |
| 履歴書v0.8 | 経歴・資格・連絡先の整合、不備防止、海外志向の補強 | 内容面は概ね完成。個人情報・写真の更新が必要 |
| 職務経歴書v0.8 | Web経験、技術力、育成、改善、リード可能性の評価 | 主材料は揃ったが、情報量と未確定年月の整理が必要 |

履歴書を完成させる効果は、書類通過率を大きく上げるというより、不備・矛盾による失点を1～3ポイント程度防ぐものと見る。通過確率の大部分は職務経歴書とエージェント推薦文で決まる。

## 3. 現在のv0.8で評価される材料

### 必須要件

- Webアプリケーション開発は2022年10月～2026年7月現在で約46か月。3年以上を満たす。
- 海外勤務への意思が強い。
- タイ約1か月半、約25か国の渡航経験があり、海外生活への抵抗が小さい。
- イタリア子会社の技術者と約2週間、英語で一対一の技術確認を行い、実作業と日本側共有まで実施した。

### 求人業務に接続する材料

- 新入社員1名へ3サイクル、約15課題、修正ラリー約45回のレビューを実施。
- 3サイクル目には先輩開発メンバー5名を巻き込み、異なるレビュー観点を経験させた。
- v1.2の自動検品機能で設計・実装を主担当。
- Promiseによる非同期処理整理、Wiresharkを用いた接続競合分析を経験。
- v1.3で約3,000行の画面クラスから約300行を段階的に分離し、状態管理を整理。
- v1.2で残った設計課題をv1.3の改善へ反映した経験がある。

### 書類上の信頼性

- 未実施だったAPI変更を成果から削除した。
- 単体テスト施策が現在未使用であること、AI効果が参考値であることを明記した。
- 正式なリーダー、Agile、Pull Requestレビュー経験を誇張していない。

## 4. 通過率を下げる要因

### 大きい弱点

1. 正式なチームリーダー、テックリード、プロジェクトリーダー経験がない。
2. 通常開発で定常的なコードレビュー経験がない。
3. Pull Request／Merge Requestベースのレビュー経験がない。
4. Scrum／Agileプラクティスの導入・改善経験がない。
5. 開発プロセス改善をチームへ定着させた実績が弱い。
6. PHP、Spring Boot、GitLab、Linux、PostgreSQL等、求人環境との直接一致が弱い。

### 中程度の弱点

1. Web開発経験は必須3年を満たすが、テックリード求人としては年数が短め。
2. 新人育成は具体的だが、対象は1名。
3. v1.2～v1.4の正確なリリース月が未確定。
4. 職務経歴書v0.8は材料を多めに載せており、企業提出版では3～4ページ相当に絞る必要がある。
5. 下限678万円は本人の現年収625万円から約8.5％増に留まる一方、職務は現地テックリードを求めており、給与アップ幅より役割拡大の方が大きい。

## 5. 情報を詰めた場合に上がる理由

残情報の確認だけで、書類通過の中心値は38%から46%、最終内定の中心値は8%から14%程度まで上がると推定する。

主な改善要因:

- v1.2～v1.4の開始・リリース月が確定し、複数リリースの主担当経験として説明できる。
- Promise、F5更新時の接続競合、`disconnect`／`start`競合について、原因・変更・テスト・再発有無を整理できる。
- v1.3の新設クラス数と状態遷移を確認し、技術選定と段階的改善を3分で説明できる。
- JaCoCoの限定範囲の実測値を確認し、目標と実績の境界が明確になる。
- エージェントの添削で情報量を減らし、1ページ目にWeb3年以上、育成、海外志向を集中できる。
- ラクス固有の志望理由を、海外一般ではなく「現地メンバーの育成と開発力向上」に接続できる。

ただし、追加情報は既存経験の証明を強くするだけで、リーダー、PRレビュー、Agile経験の不足を埋めるものではない。そのため、情報確認だけで書類通過率が70～80%へ上がるとは見積もらない。

## 6. 選考段階別の見立て

### エージェント推薦

- 現在: 55～75%、中心65%。
- 追加確認後: 65～85%、中心75%。

必須要件は満たし、育成と海外志向もあるため相談価値は高い。一方、現地テックリードとして推薦できるかは担当者判断が分かれる。

### 企業書類選考

- 現在: 25～50%、中心38%。
- 追加確認後: 32～58%、中心46%。

書類では必須条件と人物像は通る可能性がある。正式なリード、レビュー文化、Agileの不足を「今後伸ばしたい」だけで補うのは難しく、他候補者との比較で落ちる可能性も高い。

### 一次面接

- 書類通過後の現在: 30～55%、中心42%。
- 追加確認・面接準備後: 38～65%、中心52%。

育成の具体性、v1.2からv1.3への学習、海外適応は話すと強くなる。一方、PMへの不満をそのまま話す、既存コードを感情的に批判する、Agileやレビュー経験を曖昧に答えると大きく下がる。

### 最終内定

- 企業応募時点から現在: 5～12%、中心8%。
- 追加確認・書類圧縮・面接準備後: 9～20%、中心14%。

3回面接とSPIを含み、各段階で候補者比較が入るため、書類通過率より大きく下がる。応募を見送るほど低い数字ではないが、本命一本に絞る数字でもない。

## 7. 確率をさらに大きく上げるには

情報確認ではなく、新しい実務経験として次を得られれば影響が大きい。

- Git導入後にPull Requestレビューを継続運用する。
- 複数メンバーへのレビュー・育成を継続する。
- 小さくても振り返り、改善、次サイクルへの反映を記録する。
- 開発手順やAI調査方法をチームで試し、継続利用の判断まで行う。
- タスク分配、進捗確認、優先順位付けを担当する。

これらを6～12か月で具体的な実績にできた場合、同種求人の書類通過率は50～65%、最終内定率は15～30%程度まで上がる可能性がある。ただし今回の応募を遅らせる理由にはせず、現時点の市場評価をエージェントから取得する方がよい。

## 8. 推奨判断

1. 履歴書v0.8と職務経歴書v0.8をエージェントへ出す。
2. 「企業提出前の添削用」と明記する。
3. エージェントに、推薦可否と年収レンジの妥当性を率直に確認する。
4. 会社PCでP0項目を確認し、企業提出版は情報を3～4ページ相当に圧縮する。
5. ラクスだけに依存せず、海外志向・育成経験を評価するプレイヤー寄り求人も並行して探す。
